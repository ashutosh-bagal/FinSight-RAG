# FinSight-RAG

A role-aware Retrieval-Augmented Generation (RAG) assistant for answering questions over company 10-K financial filings (currently Apple and Amazon). Retrieval is filtered by role *at the vector-database layer* — a `public` user's query never even retrieves finance-tagged chunks, rather than relying on the LLM to withhold information after the fact.

## How it works

```
PDF filings (data/raw/) 
      │  ingest.py — chunk + tag with company/role metadata
      ▼
ChromaDB (chroma_db/, collection "finance_filings")
      │  rag.py — retrieve() filters by role at query time
      ▼
Groq LLM (openai/gpt-oss-120b) — generates grounded answer
      │
      ▼
FastAPI (src/api.py) ──► Streamlit UI (src/app.py)  or  static HTML client (web/index.html)
```

### Pipeline stages

1. **Ingestion** ([src/ingest.py](src/ingest.py)) — Loads the Apple and Amazon 10-K PDFs, splits them into ~800-character chunks (150-character overlap) with `RecursiveCharacterTextSplitter`, embeds them with `sentence-transformers/all-MiniLM-L6-v2`, and stores them in a persistent ChromaDB collection (`finance_filings`). Each chunk is tagged with `company` and a `role` (`public` or `finance`), based on the PDF page number — pages before each filing's financial-statements section are tagged `public`, everything from that page onward is tagged `finance`.

2. **Guardrails + query rewriting + retrieval** ([src/rag.py](src/rag.py)):
   - `is_in_scope(query)` — an LLM classifier that rejects questions unrelated to financial filings (e.g. "write me a poem") before any retrieval happens.
   - `rewrite_query(query)` — an LLM step that rephrases casual/vague questions into terms more likely to match formal filing language (e.g. "how much did they spend on research" → "R&D expense"), while leaving already-precise questions untouched.
   - `retrieve(query, role, n_results)` — embeds the (rewritten) query and runs a ChromaDB similarity search, applying a `where={"role": "public"}` filter unless the caller's role is `finance`. This is the RBAC boundary: a `public` caller's query physically cannot retrieve finance-tagged chunks.
   - `build_prompt(query, chunks)` — assembles a context-grounded prompt instructing the model to answer only from retrieved context, refuse to speculate/give investment advice, and decline politely if the role isn't authorized.
   - `check_output(answer)` — an output guardrail that flags responses containing likely PII or hallucinated specifics, returning a safe refusal instead.
   - `ask(query, role)` / `ask_with_context(query, role)` — the orchestrating functions tying the above together; `ask_with_context` also returns the retrieved chunks (used by the evaluation script).

3. **API** ([src/api.py](src/api.py)) — FastAPI app exposing:
   - `POST /ask` — `{ "question": str, "role": "public" | "finance" }` → `{ "answer": str }`
   - `POST /verify_passcode` — checks a submitted passcode against `FINANCE_PASSCODE` in the environment (intended as a lightweight gate for elevating to the `finance` role in a client)

4. **Frontends**:
   - **Streamlit** ([src/app.py](src/app.py)) — a minimal chat UI with a role selector and a loading spinner, calling the FastAPI backend at `http://127.0.0.1:8000/ask`.
   - **Static HTML** ([web/index.html](web/index.html)) — a themed single-page client with a role toggle badge and example prompts, calling the same API directly from the browser.

5. **Evaluation** ([src/evaluation.py](src/evaluation.py), [src/eval_set.py](src/eval_set.py)) — Runs a fixed set of ~20 question/role/ground-truth triples through `ask_with_context`, writes a per-question Markdown transcript to `evaluation_report.md`, then scores the run with [Ragas](https://github.com/explodinggradients/ragas) on four metrics — `faithfulness`, `context_precision`, `context_recall`, `answer_relevancy` — using `gpt-4o-mini` as the judge LLM and `all-MiniLM-L6-v2` for embeddings. Scores are written to `ragas_scores.csv`. The eval set deliberately includes both `public`- and `finance`-role questions and several out-of-scope / refusal cases to exercise the guardrails, not just retrieval quality.

## Project layout

```
data/raw/            Source 10-K PDFs (Apple, Amazon)
chroma_db/           Persistent ChromaDB store (generated by ingest.py)
src/
  ingest.py          One-off script: chunk, tag, embed, and index the filings
  rag.py             Core RAG logic: guardrails, query rewriting, retrieval, generation
  api.py             FastAPI backend
  app.py             Streamlit frontend
  eval_set.py        Hand-written evaluation questions + ground truths
  evaluation.py       Runs the eval set through the pipeline and scores it with Ragas
web/index.html       Standalone HTML/JS frontend (no build step)
evaluation_report.md  Latest generated eval transcript (question/answer/context)
ragas_scores.csv      Latest generated Ragas metric scores
```

## Setup

**Requirements:** Python 3.10+, API keys for [Groq](https://console.groq.com) and [OpenAI](https://platform.openai.com) (OpenAI is only used as the Ragas judge model).

```bash
python -m venv venv
venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

Create a `.env` file in the project root:

```
GROQ_API_KEY=your_groq_key
OPENAI_API_KEY=your_openai_key      # only needed to run evaluation.py
FINANCE_PASSCODE=your_chosen_passcode
```

> `.env` is git-ignored — never commit real keys.

## Running it

**1. Ingest the filings** (only needed once, or after adding/changing PDFs):

```bash
python src/ingest.py
```

This builds the `chroma_db/` vector store from the PDFs in `data/raw/`.

**2. Start the API:**

```bash
uvicorn src.api:app --reload
```

**3. Start a frontend** — pick one:

```bash
streamlit run src/app.py          # Streamlit UI
# or just open web/index.html directly in a browser
```

**4. Run the evaluation suite** (requires the API's dependencies and both API keys; run from `src/` since `evaluation.py` imports `rag` and `eval_set` directly):

```bash
cd src
python evaluation.py
```

This regenerates `evaluation_report.md` and `ragas_scores.csv`.

## Design notes

- **RBAC is enforced at retrieval, not at the prompt.** The `public` role's ChromaDB query is filtered with `where={"role": "public"}`, so finance-tagged chunks are never fetched for that role — a jailbroken prompt can't leak what was never retrieved.
- **Two independent LLM guardrails** bound the pipeline: an input classifier (`is_in_scope`) rejects off-topic questions before retrieval, and an output checker (`check_output`) screens generated answers for leaked PII or unsupported hallucinated figures before they're returned.
- **Query rewriting** is a targeted, conditional step — it only rephrases vague/casual questions into filing-style language, leaving already-precise questions unchanged, to improve retrieval recall without distorting user intent.
- **Swap-able judge/embeddings for eval** — Ragas evaluation uses `gpt-4o-mini` as an independent judge model (distinct from the Groq model that answers questions) to avoid the pipeline grading its own homework.

## Known limitations / next steps

- Currently indexes only two filings (Apple, Amazon FY2025 10-Ks); `ingest.py`'s `files` dict would need extending for more companies.
- Role gating in `data/ingest.py` is a heuristic based on a single "finance section start page" per filing — not derived from actual document structure, so it would need adjustment per filing format.
- `/verify_passcode` checks a shared passcode but the frontends don't currently use it to gate the `finance` role — role is just a client-supplied form field with no server-side auth around the passcode check.
